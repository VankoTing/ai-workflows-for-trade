# 角色与权限设计（RBAC）

> 本文件是「企业知识库 + RAG」系统的权限设计基准。改权限先改这里，再改代码。

## 1. 角色定义

| 角色 | 人数 | 说明 |
| --- | --- | --- |
| `gm` 总经理 | 1 | 全局可见，含成本与合同 |
| `manager` 销售经理 | 1 | 团队级可见，负责审批 |
| `sales_a` 业务员 A | 1 | 仅看自己的客户 |
| `sales_b` 业务员 B | 1 | 仅看自己的客户 |
| `sales_c` 业务员 C | 1 | 仅看自己的客户 |

> 业务员 A/B/C 是同一角色 `sales` 的三个账号（数据靠 `owner` 区分），不要写成三个角色——**角色定义"能做什么"，账号定义"管哪些客户"**。这是 RBAC 的基本功。

## 2. 数据密级（Data Classification）

每份资料在入库时打一个密级标签 `sensitivity`：

| 密级 | 含义 | 典型资料 |
| --- | --- | --- |
| `public` | 公开 | 产品目录、宣传册、官网文章 |
| `internal` | 内部 | 选型表、通用价格表、证书 |
| `confidential` | 机密 | 报价单、投标文件、客户联系方式 |
| `restricted` | 绝密 | 采购合同、成本、利润 |

## 3. 权限矩阵（角色 × 密级 × 数据范围）

| 资料类型 | 密级 | 总经理 | 销售经理 | 业务员 A/B/C |
| --- | --- | :--: | :--: | :--: |
| 产品目录 / 宣传册 | public | ✅ 全部 | ✅ 全部 | ✅ 全部 |
| 选型表 / 证书 | internal | ✅ 全部 | ✅ 全部 | ✅ 全部 |
| 通用价格表（对外口径） | internal | ✅ 全部 | ✅ 全部 | ✅ 全部 |
| 报价单 | confidential | ✅ 全部 | ✅ 本团队 | ⚠️ **仅 owner = 自己** |
| 客户联系方式 | confidential | ✅ 全部 | ✅ 本团队 | ⚠️ **仅 owner = 自己** |
| 投标文件 | confidential | ✅ 全部 | ✅ 本团队 | ⚠️ 仅自己参与的项目 |
| 采购合同 | restricted | ✅ 全部 | ❌ | ❌ |
| 成本 / 利润数据 | restricted | ✅ 全部 | ❌ | ❌ |
| 运营文章 / 视频素材 | internal | ✅ 全部 | ✅ 全部 | ✅ 全部 |

## 4. 动作权限（能不能"做"，不只是"看"）

| 动作 | 总经理 | 销售经理 | 业务员 |
| --- | :--: | :--: | :--: |
| 知识库问答 | ✅ | ✅ | ✅ |
| 生成报价草稿 | ✅ | ✅ | ✅（提交后需上级审批） |
| 审批报价 | ✅ | ✅ | ❌ |
| 查看全局经营分析 | ✅ | ⚠️ 仅本团队 | ❌ |
| 导入 / 删除资料 | ✅ | ❌ | ❌ |

## 5. 实现机制（关键）

**不是"检索出来再隐藏"，而是"根本不让检索到"。**

1. **入库时打标**：每个切片（chunk）写入元数据：
   ```json
   {
     "doc_id": "QUOTE_20260812_MC某地区",
     "source": "报价单/20260812-MC-某地区/xxx.xlsx",
     "sensitivity": "confidential",
     "owner": "sales_b",          // 负责的业务员
     "team": "export_1",          // 所属团队
     "project": "20260812-MC-某地区",
     "updated_at": "2026-08-12"
   }
   ```
2. **检索时过滤**：根据当前登录用户的角色，拼一个过滤条件（Chroma 的 `where` / SQL 的 `WHERE`），只在这个子集里做向量检索。
   - 总经理：无过滤
   - 销售经理：`team = 本团队 AND sensitivity IN (public, internal, confidential)`
   - 业务员：`owner = 自己 OR sensitivity IN (public, internal)`
3. **生成时兜底**：把命中的资料连同**来源**一起给模型，回答必须带引用（可溯源 = 能追责）。

> 为什么强调"不让检索到"？因为如果先检索到再隐藏，模型可能已在生成时"看到"了机密内容，一句话就能泄露。**权限必须在检索前生效。**
