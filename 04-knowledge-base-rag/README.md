# 企业知识库 RAG 系统

> 把企业内部散落的非结构化资料（产品资料 / 报价单 / 合同 / 投标文件）沉淀成**可检索的知识库**，
> 并在其之上打通 **客户询价 → 参考报价表 → 技术规格书** 的业务闭环。
>
> **全流程本地部署，数据不出内网。**

---

## 一、它解决什么真实问题

| 痛点 | 具体表现 | 本项目的做法 |
|---|---|---|
| **找资料慢** | 资料散落多目录，查一份历史报价要翻很久 | 全量入库 + 语义检索，带引用来源 |
| **知识会过期** | 换供应商后新老价格并存，**检索分不清哪份作数** | 版本与时效治理（见下） |
| **权限敏感** | 报价单、合同不能让所有角色看到 | 权限过滤**前置到检索之前** |
| **没法衡量** | 改完只能"感觉变好了" | 评测集 + 系统底线检查，出量化数字 |
| **重复劳动** | 每次询价都要人工翻历史报价 | 询价单 → 参考报价表自动生成 |

## 二、超出"基础 RAG 教程"的四个设计

### 1. 权限过滤在检索之前，不是之后

先检索再隐藏，模型在生成阶段已经"读"到了机密内容，**一句话就能泄露**。
所以权限被翻译成向量库的过滤条件，**在检索时就生效**。

### 2. 文档有版本和时效

给每份资料自动标注 **日期 / 版本号 / 文档家族 / 状态 / 内容指纹**（全部从文件路径推断，不需读内容）。
状态判定分四步，**越往后越保守**：

```
① 内容指纹相同            → 判「重复副本」（检索只留一份）
② 内容不同 + 日期可信 + 相差≥30天 → 判「版本取代」
③ 其余                    → 列成「待裁决冲突」
④ 人工裁决优先             → 生成可点选的裁决页，人拍板后系统照办
```

> **核心原则：「哪一版作数」是业务决策，程序不该擅自判死。**

### 3. 混合检索：精确标识不交给语义检索

**踩过的坑**：问「GKV326 闸阀符合什么标准」，语义检索返回了**另一个型号**（球阀）的段落，
模型据此把闸阀答成了球阀 —— 因为同类规格书在语义空间里几乎一样近。

**解法**：先从问题里抽出「精确标识」（型号、单号），用**字符串精确匹配**捞取；
语义检索只负责补"问题里没有型号"的那部分召回。

### 4. 评测集：让优化不再是"感觉"

- 黄金集：答案全部从真实资料逐条核对，**绝不编造**
  （编造答案的评测集比没有更糟 —— 会把错误方向验证成"有效"）
- 三项**系统底线检查**：版本隔离 / 权限隔离 / 时间过滤，必须 0 违规
- 每次改动输出与基线的 ↑/↓ 对比

## 三、架构

```
① 入库（离线）
   资料 → 解析 / OCR（逐页决策）→ 清洗（去页眉页脚噪音）→ 切片 → 向量化 → 向量库
        └─ 同时写入元数据：密级 / 来源 / 日期 / 版本 / 文档家族 / 内容指纹

② 治理
   内容指纹去重 · 版本与时效判定 · 冲突裁决（人工）

③ 检索（在线）
   提问 → 权限过滤 + 时间过滤 → 混合检索（精确标识 + 语义召回）→ 单文件限流

④ 生成
   本地 LLM 依据资料生成，强制带引用来源（知识血缘）

⑤ 业务闭环
   客户询价单 → 参考报价表（匹配历史报价）→ 技术规格书（抽产品参数）
```

## 四、快速开始

```bash
# 1. 依赖
pip install -r requirements.txt

# 2. 模型（本地，Ollama）
ollama pull qwen2.5:7b      # 生成模型
ollama pull bge-m3          # 向量模型

# 3. 指向你的资料目录（配置文件里改这一个变量）
#    src/config.py  →  DATA_ROOT = Path(r"你的资料目录")

# 4. 入库（增量、可中断续跑）
python src/ingest/build_index.py --dir "你的资料目录" --workers 4

# 5. 问答
python src/search/ask.py "GKV225 球阀的压力等级是多少？" --show

# 6. 评测
python scripts/run_eval.py --show-fail
```

**控制面板**（可选）：`python panel/server.py` → 打开 `http://127.0.0.1:8777`

## 六、⚠️ 数据说明（重要）

**本仓库不含任何真实企业资料。**

- 所有客户名称、业务员姓名、公司名称、真实价格、资料文件**均已脱敏或未包含**
- 仓库里的示例、评测集问题、测试数据均为**模拟数据**
- 脱敏由 `scripts/sanitize_repo.py` 统一执行，敏感词表**外置**在 `data/mask_terms.txt`（不进仓库）
- 真实使用时，资料放在本地目录，通过配置指向 —— **数据全程不出本机**

## 九、关于 AI 协作（诚实说明）

本项目采用**人机协作**方式完成：

- **我负责**：需求定义、技术方案与架构决策、关键取舍拍板、业务规则确认，以及**逐项验证输出是否正确**
- **AI Agent 负责**：具体代码实现、文档撰写、重复性调试
- **验证方式**：真实数据小样本试跑 → 人工核对 → 全量执行；评测集做回归；关键结论必须有可复现命令与实际输出
