## 数据流

1. **输入**：从海关数据平台导出的候选公司名单（公司名 + 国家）。
2. **背调**：Agent 依次调用「官网调研 → LinkedIn 检索 → 邮箱挖掘」三类工具，产出结构化字段。
3. **分级**：按「产品匹配度 + 是否拿到决策人邮箱」映射到 A / B / C。
4. **生成**：对 A 类客户生成个性化开发信，写入结果表备注列。
5. **复检**：AI 二次核对邮件内容（准确性 / 个性化 / 风险）。
6. **触达**：确认后经 Gmail MCP 批量发送。

## 技术组成

| 环节 | 使用 |
| --- | --- |
| Agent 运行时 | OpenClaw（本地部署） |
| 提示词 | 结构化多步指令模板（角色 + 分步 SOP + 输出格式约束） |
| 数据源 | 海关数据平台、公司官网、LinkedIn |
| 联系方式挖掘 | Hunter.io、Apollo |
| 发送 | Gmail MCP |
| 结果承载 | Excel（「高潜力客户」工作表） |

## 踩过的坑与思考

- **跨会话记忆丢失**：Agent 在会话之间会遗忘上下文（例如昨天采集的客户信息今天丢失），导致需要重复采集、重跑工作流。**改进方向**：把中间结果持久化到外部存储（表格 / 数据库），而不是依赖会话记忆。
- **成本不可预期**：同样的操作，在不同时间或不同账户状态下消耗的额度不同，长链路多步任务尤其明显。**改进方向**：精简提示词、减少无谓的多阶段编排，把「一步能出结果」的任务合并。
- **输出质量需要人工兜底**：业务场景（如技术规格书）必须经人工与技术部门复核后才能对外，AI 不适合直接对客户输出未经审核的技术内容。
